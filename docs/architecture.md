# 模块与运行语义

UI → typed API → Tauri command → Service。Commands 处理序列化和阻塞任务转移，业务状态由 Service 和各管理器所有。持续状态通过 Tauri events 输出；订阅在组件卸载时解除，包括订阅注册尚未完成时的竞态。

## 捕获与结果

WGC 在专用控制线程运行 `windows-capture` 的 free-threaded session；回调检查代数和暂停标记，按捕获频率限流后将 RGBA 转 RGB。ADB 用独立 runtime 执行可取消的 screencap，按完整剩余间隔睡眠。两者共用 `Frame`。

只保留一个最新待处理帧及一个当前预览帧（Arc 共享）；覆盖待处理帧会记录丢弃。JPEG 预览最长边 1280、质量78、最高每秒4次。OCR读取最新帧，没有工作队列增长。64×64 RGB 差值与上一张成功识别帧比较，阈值可配置；手动单次识别绕过变化检测。

窗口身份含 HWND、PID、进程创建时间、窗口类和销毁事件代数。每100ms检查当前身份、最小化和可捕获状态。关闭/重建后的 HWND 不能沿用旧选择。捕获 generation 和 OCR epoch 阻止旧窗口、停止前的推理结果回写。发布结果和改变 generation 使用同一短临界区，消除检查后又切换的竞态。

OCR历史保存结果加对应压缩预览，长度受配置限制；只为最新识别帧保存一张完整分辨率 RGB 图。历史中的边界框始终画在对应识别帧上。原图导出只针对最新识别帧或当前实时帧，以免把历史结果与新图混用。

## 推理所有权与取消

UI 主进程与 CPU / CUDA worker 用本地 stdin/stdout NDJSON 通信，没有 HTTP 服务和监听端口。每个 worker 的主线程独占全部 llama/mtmd 对象，模型和 projector 跨请求常驻，每次创建新的推理上下文。GPU 缺失不会破坏 UI 加载器。

worker 只处理一个请求。停止 OCR / 切换目标立即改变 epoch：已经进入原生调用的那次推理可以完成，但结果被丢弃；新推理等待这个有界任务退出。180秒超时会终止 worker 并进入错误状态。卸载等待当前请求并终止 worker；应用退出设置 closing 标记，等待请求时每50ms检查它，随后杀死并回收子进程。模型切换先释放旧进程，再加载新模型。

捕获和推理不持有 UI 线程；大文件导入、哈希、PNG/JPEG 编码转移到阻塞线程。模型文件操作串行，加载/删除/配置变更使用生命周期锁，避免模型路径变更和文件删除互相竞争。

## 模型管理

下载先写 `.gguf.part`。206必须匹配offset与总大小，200会重写而非错误追加；网络失败保留部分文件，完整但校验失败会移除。重试最多三次。成功校验主模型和mmproj后才写原子 manifest；列举时还核对大小，每次加载重新验证 SHA-256。导入先验证两个输入，再复制、校验、写 manifest，失败回滚本次创建的文件。共享 mmproj 在其他已安装模型引用时不会被删除。

## 扩展点

统一 OcrResult / OcrBlock 是未来翻译消费者的输入。CaptureShared 是捕获源的汇合点，ChangeDetector 可替换为区域级检测。当前没有翻译请求、文本改写或透明覆盖层。

性能值来自真实捕获计数、成功识别时间和测量的分阶段时长。显存遥测暂不可获取，UI明确显示「不可用」。OCR次数/分钟是最近60秒成功次数，不是理论吞吐量。
