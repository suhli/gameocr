# 翻译质量与语料

`tests/translation/corpus.json` 是手工构造的游戏风格语料，包含原文、人工编写的参考译文、类型和待填写的 humanReview。不是从真实游戏采集，也不代表所有游戏。CLI 输出原始实际译文；没有伪造人工评分。

首轮 13 条真实 Q4_K_M 推理记录见 `test-results/translation-cpu.json` 和 `translation-cuda.json`。覆盖 NPC 对话、日语敬语、角色语气、技能/道具与数字、术语约束、多行菜单、中日英混排、拟声词、不完整 OCR、受控上下文和首尾重复。每条记录都保存 EOS/预算停止原因、实际生成 Token 和时间。

本次观察（开发者检查，不是独立人工验收）：

- 英译中、日译中、中译英、中译日样例均生成目标语言的可理解结果。
- 术语样例中的 Phoenix、Limit Break、Eikon 遵循该请求提供的译法。它们没有进入默认术语表。
- 菜单的四行结构与道具样例中的 200/5 数字得到保留。
- 拟声词 `ドカーン` 被翻成含残留假名的 `咚ーン`，说明质量仍有边界。
- 不完整英文在 CPU 输出中保留不完整语义，GPU 输出增加“的话”；不能根据 fluent 外观判定完整或忠实。
- 相同开头/末尾请求（中间经过不同语言、术语和上下文）返回相同译文，支持请求间 KV 隔离的实测结论。

后续人工验收请分别记录准确性、完整性、流畅性、术语一致性、语气保留、格式保持，以及幻觉/额外解释。每个维度应有评分、理由、评价人和日期；未评价字段保持 null。自动数字/术语/换行检查只提供线索，不能替代这些维度，也不以 BLEU 或单一字符串相等作为通过条件。

低温度实验使用同一模型和语料另存报告；短句耗时受 Prompt 长度、生成长度、CPU/GPU、缓存热度影响。不能仅因温度降低就声称更快或更准确。
