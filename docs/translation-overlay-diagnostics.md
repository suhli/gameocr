# 游戏字幕本地诊断（2026-10-29 至 2026-10-30）

用户确认点击“翻译当前帧”后没有切回被捕获的游戏窗口。现有策略仅允许当前游戏处于前台时显示独立字幕，因此这一操作符合后台自动隐藏条件；预览译文不受此条件限制。本次保留该策略，不声称已经排除其他原生显示问题。

为便于继续排查，新增 `%LOCALAPPDATA%\GameOCR\logs\gameocr.log` 本地滚动 JSONL 日志，并细分界面状态。最多保留当前文件和三份备份，每份 2 MiB；后台有界队列写入，不让磁盘阻塞识别线程。记录字幕窗口创建/失败、译文接收结果、显示条件、坐标/尺寸、渲染器启动与尺寸等待、绘制确认、原生显隐及应用生命周期。截图、识别正文、翻译正文不写入日志。

原生定位、缩放、显示和隐藏失败现在进入日志；“游戏字幕窗口已显示”只在当前快照已经确认绘制、原生窗口可见时发布。主界面持续提示“切回目标游戏才会显示字幕”。渲染器上报失败不阻断正常渲染；渲染/确认失败仍清空字幕，避免残留。

## 已完成验证

- Svelte/TypeScript：0 错误、0 警告。
- 前端单元测试：14 项通过。
- Rust 桌面库测试：46 项通过，包含日志轮转/容量上限、逐行 JSON 完整性、重启追加、目录不可用后恢复和 UTF-8 错误长度限制。
- 无界面 Edge：6 组通过。新增验证实际字幕组件上报启动状态、视口尺寸不符时暂不确认、调整尺寸后确认，以及模拟 IPC 失败后上报并清空内容。
- 格式及差异检查通过。

证据位于 [overlay-logs-2026-10-29](test-results/overlay-logs-2026-10-29/)，该工作在 10 月 30 日继续完成。浏览器测试仍使用模拟输入和通信，不是实际游戏/Win32 窗口验收。遵照用户此前要求，本轮没有控制桌面，也没有改变真实游戏窗口焦点。

使用新版复现后，先查看 `overlay.state` 的原因，再将同一 serial 的 `overlay.renderer`、`overlay.render_ack` 和 `overlay.native` 对照。默认无新 OCR 观察 15 秒后字幕会过期，主界面预览可继续显示对应历史截图的译文；如已过期，需要重新识别后再切回游戏。
